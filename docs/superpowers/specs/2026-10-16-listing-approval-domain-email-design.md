# Listing approval and domain transition

Approved by the owner on 16 October 2026 in the implementation request.

Every seller listing requires an explicit admin publication decision. Submission is private until approval; listing approval grants no condition/certification badge. Benchmark review and physical inspection remain independent. Benchmark approval alone never publishes a listing. Refusal and changes-requested decisions require a reason visible to the seller, with review history retained. Seller edits to hardware, description, condition, defects or photos invalidate publication approval and evidence badges; price-only edits preserve approval. Administrative hide/delete restrictions remain independent and cannot be cleared by submission or review. Existing seller listings enter pending review without manufactured approvals or data deletion. Company stock already requires an authorized admin publication operation.

Use a database publication guard so every existing save/resume/relist/admin path observes approval. Keep availability and review metadata separate; submitted unapproved availability is `pending_review`. Add `review_status` (`draft`, `pending`, `approved`, `changes_requested`, `rejected`), `review_note`, `reviewed_revision`, `reviewer_id`, `reviewed_at`, and `review_submitted_at` to seller listings. Add owner/admin-readable immutable `listing_review_history` with cascading listing deletion. Preserve reference IDs, optimistic concurrency, private contacts, file authorization and integer piastres. Public listing/contact/evidence access requires approved current content. Allow evidence uploads before publication for owned nondeleted draft/pending/rejected/paused listings; signed-in buyers only see evidence of public listings.

Public RPCs: `review_listing(lid uuid, expected_updated_at timestamptz, decision text, note text)` and `admin_listing_review_queue(term text default '', filter_status text default 'pending', page_number integer default 1)`. Queue response: `{total, items:[{listing: <SellerListing row>, seller:{display_name, governorate}}]}`, 20 per page, reference/UUID/title search. Decision values: approved, changes_requested, rejected. Review history exposes id, listing_id, revision, decision, note, reviewer_id, reviewed_at. Both server actions and SQL enforce authorization and refusal reasons.

Seller submission keeps form payload status `listed` as intent; the database chooses actual public/pending state. UI shows separate review state, latest feedback and history. New admin Listing reviews navigation and queue link to product workspaces by reference. Existing benchmark and physical queues stay separate. Arabic/English copy must explain pending visibility and refusal/resubmission.

Primary site: https://pc-ex.store; www redirects permanently to apex with path/query preserved. Canonicals, sitemap, Auth callbacks/reset links, email templates, local backend SITE_URL and recovery deploy configuration use the apex. Preview environments stay isolated. Retain secure localhost development callbacks and narrowly scoped production callbacks; no wildcard external redirects.

Branded sending: accounts@pc-ex.store through the existing Brevo SMTP account after domain authentication. Support: support@pc-ex.store forwards to the owner's explicitly chosen Gmail. Verify authoritative DNS, Brevo verification/DKIM/DMARC and inbound forwarding before declaring complete. Preserve unrelated DNS/MX records and do not purchase services. If a login or provider approval blocks setup, complete other work and identify the exact remaining action.

Acceptance: SQL tests cover pending invisibility, role boundaries, reason requirements, stale decisions, edit invalidation, price preservation, bypass prevention and independent evidence/inspection decisions. Static/build suites and focused real-backend browser acceptance use disposable fixtures only.
